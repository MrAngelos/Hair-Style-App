# Hair Styler — лендинг «фен-стайлер 2 в 1»

Лендинг из трёх полноэкранных слайдов. Реакт + TypeScript + Vite, CSS Modules, архитектура — Feature-Sliced Design.

- **Desktop (> 900px)** — вертикальная колода слайдов со `scroll-snap`, слева круговой селектор с иконками.
- **Mobile (≤ 900px)** — одна вертикальная лента со всеми тремя слайдами, селектор скрыт.

## Запуск локально

```bash
# 1. установить зависимости
npm install

# 2. запустить dev-сервер
npm run dev
```

Приложение откроется на **http://127.0.0.1:3000** (хост и порт заданы в `vite.config.ts`).

Сборка и проверка продакшн-версии:

```bash
npm run build     # tsc -b + vite build → dist/
npm run preview   # локальный предпросмотр собранной версии (http://localhost:4173)
```

Проект разложен по слоям Feature-Sliced Design: `app → pages → widgets → features → entities → shared`.
Алиасы `@app`, `@pages`, `@widgets`, `@features`, `@entities`, `@shared` описаны в `vite.config.ts` и `tsconfig.app.json`.

```
src/
├── main.tsx                    точка входа: createRoot + StrictMode
├── app/
│   ├── App.tsx                 корневой компонент (<Home />)
│   ├── providers/              провайдеры приложения
│   └── styles/global.css       сброс стилей, фон страницы
├── pages/Home/                 страница: десктопная колода + мобильная лента
├── widgets/
│   ├── SlideShow/              десктопный слайдер и боковой селектор
│   │   ├── SlideShow.tsx       колесо / клики → скролл к слайду
│   │   ├── SlideDeck.tsx       скролл-контейнер, клоны для цикличности
│   │   ├── Slide.tsx           секция слайда, карточка и её масштаб
│   │   ├── SlideDuo.tsx        вёрстка слайда 1
│   │   ├── SlideLight.tsx      вёрстка слайда 2
│   │   ├── SlideCompact.tsx    вёрстка слайда 3
│   │   └── SideWheel.tsx       круговой селектор с иконками
│   └── MobileFeed/             мобильная версия — лента из трёх секций
├── features/slideNavigation/
│   ├── atoms.ts                jotai-атом активного слайда
│   ├── useActiveSlide.ts       IntersectionObserver → индекс активного слайда
│   └── useScrollToSlide.ts     плавный скролл к слайду через requestAnimationFrame
├── entities/slide/
│   ├── model.ts                данные трёх слайдов (тексты, картинки, иконки)
│   └── types.ts                типы SlideData / DeviceItem
└── shared/ui/
    ├── Icon/                   иконки селектора (inline SVG, currentColor)
```

Статика лежит в `public/`: `images/` (фото слайдов и устройств), `icons/` (SVG-глифы селектора), фавиконки.

## Как это работает

### Переключение слайдов (desktop)

- Контейнер `.deck` — нативный вертикальный скролл с `scroll-snap-type: y mandatory`.
- В колоде пять секций: клон последнего слайда, три реальных, клон первого. Когда скролл доезжает до клона, `scrollend` мгновенно подменяет его реальным слайдом — заворот получается бесшовным.
- Активный слайд считается `IntersectionObserver` по максимальной площади пересечения; индекс хранится в jotai-атоме и используется колесом.
- Колесо мыши и трекпад: порог 30px и блокировка на 900ms, чтобы одно движение не пролистывало несколько слайдов.
- Скролл к слайду — собственная rAF-анимация (520ms, ease-out). Нативный `smooth` браузер отменяет, если во время анимации продолжают приходить события колеса, из-за чего слайд «застревает» на полпути.
- Вход слайда — CSS-transition: карточка выезжает снизу (`opacity` + `translate: 0 80px → 0`), контент догоняет её с задержкой 120ms.

### Боковой селектор (только desktop)

- Иконки расставлены по окружности (`STEP = 20°`, `R = 320px`); текущая иконка всегда стоит в центре колеса.
- При смене слайда вся орбита поворачивается на ±20°, слот компенсирует поворот — иконки едут по дуге и остаются вертикальными. При завороте через край иконка проходит длинный путь по окружности и не срезает через центр.
- Активная иконка крупнее (103px против 74px), выделена светлым кружком и подписью слайда; остальные приглушены (`#ADACAC`).
- Клик по иконке вызывает `useScrollToSlide(index)` и плавно скроллит к нужному слайду.
- Колесо центрируется по вертикали: контейнер растянут на всю высоту вьюпорта, центр орбиты — `top: 50%`.
- На ширине ≤ 900px селектор скрыт.

### Адаптив

**Desktop.** Слайд свёрстан в дизайн-фрейме `1240×800`; карточка масштабируется целиком. `ResizeObserver` на секции считает
`scale = min(1, (W − 220) / 1240, (H − 100) / 800)` и пишет результат в CSS-переменную `--slide-scale`.
От коэффициента зависят размер карточки, её `border-radius` и `transform: scale()` контента — поэтому на любом окне карточка сохраняет пропорции `1240:800` и не растягивается по ширине отдельно от высоты. На референсном `1920×900` карточка ровно `1240×800`.

**Mobile.** Мобильная версия свёрстана в дизайн-фрейме `320×844` и масштабируется по тому же принципу. Содержимое каждой секции обёрнуто в «сцену» `.stage` шириной `320px` с `transform: scale(var(--m-scale))`, а `--m-scale = ширина ленты / 320` считается в `ResizeObserver` (`MobileFeed.tsx`). Высоты секций и отступы между ними умножаются на тот же коэффициент (`calc(750px * var(--m-scale))`, `calc(900px * var(--m-scale))`, …), поэтому вертикальный ритм масштабируется вместе с содержимым. На `320px` коэффициент равен `1` и вёрстка рендерится как свёрстана, на `390px` всё крупнее в 1.22×, на `430px` — в 1.34×.
